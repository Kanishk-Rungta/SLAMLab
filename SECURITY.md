# Security

Only the current default branch receives security maintenance. Research software
may contain unsafe parsers or historical dependencies; execute untrusted data
inside an isolated environment.

For a vulnerability, use GitHub's **Report a vulnerability** option on the
repository Security tab if available. Otherwise use a private contact explicitly
published on a maintainer's GitHub profile. Do not include exploit details,
credentials or private recordings in a public issue. No response-time guarantee
or unpublished reporting address is implied.

For ordinary simulation or installation bugs, use a public issue after removing
machine-specific information. Never put secrets in sample configurations.
