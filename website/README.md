# Future SLAMLab website

The technical repository and Markdown learning content are the current product.
No speculative frontend is included. A later website can consume [docs](../docs/README.md),
[algorithm guides](../algorithms/README.md) and explicit validation states.

Recommended next phase: build a static documentation portal with source-linked
navigation, algorithm/sensor comparison filters and small interactive explanations
of uncertainty, pose graphs and alignment. Keep measured experiment reports
separate from analytic teaching fixtures. Simulator execution and large native
builds should remain user-controlled outside a static browser tutorial.

Before adding a stack, define the content schema, status vocabulary and link
validation so public claims stay synchronized with actual repository evidence.
Do not publish raw/private recordings or import the earlier project website's
internal content automatically.
